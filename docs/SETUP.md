# Клуб бадминтона

Сайт клуба с онлайн-записью: **React + Vite + TypeScript**, сервер **Node.js + Express**, база **SQLite + Prisma**.

**PostgreSQL и Docker для запуска на ПК не нужны.** Пользователи, занятия, записи, сессии и настройки сохраняются в обычном файле `data/club.db`, а не в localStorage. С базой работает только Node.js-сервер.

## Быстрый запуск на Windows

Установите Node.js **22.12+** (ваша версия 24 тоже подходит). В папке репозитория:

```powershell
git pull --ff-only
npm ci --ignore-scripts
npm run setup
npm run admin:create
npm run dev
```

Откройте **http://localhost:5173**. Для остановки — `Ctrl+C`. Для последующих запусков достаточно `npm run dev`.

`setup` автоматически:

- создаёт `.env`, если его ещё нет;
- генерирует случайный `SESSION_SECRET`, если осталось значение-заглушка;
- переключает старый `DATABASE_URL` с PostgreSQL на SQLite, предварительно сохранив `.env` в игнорируемый Git файл `.env.postgresql-<время>.bak`;
- генерирует Prisma-клиент, создаёт файл БД, применяет миграции и добавляет подтверждённые цены, недельное расписание, площадки и известных тренеров;
- не создаёт администраторов и паролей по умолчанию.

Данные старой PostgreSQL **не удаляются и не импортируются автоматически**. Если вы успели наполнить старую базу, перенос данных — отдельная операция. При описанных ранее ошибках подключения локальных данных в ней ещё нет.

### Администратор

```powershell
npm run admin:create
```

Введите email, имя и пароль (минимум 12 символов, ввод скрыт). Команда создаёт отдельный аккаунт администратора и не повышает права существующего пользователя по совпадению email. Войдите на сайте и откройте «Панель администратора» в кабинете.

Для защищённой консоли хостинга поддерживаются `ADMIN_EMAIL`, `ADMIN_NAME`, `ADMIN_PASSWORD`. Не указывайте пароль аргументом командной строки и не сохраняйте секреты в Git.

### Настройки

В `.env`:

```dotenv
DATABASE_URL="file:./data/club.db"
WEB_ORIGIN="http://localhost:5173"
PORT=3001
```

`SESSION_SECRET` заполняет `setup`; его не нужно отправлять в чат. Путь `file:./data/club.db` отсчитывается от корня проекта для всех команд. Можно использовать абсолютный путь, например `file:C:/SitesWorks/club-data/club.db` на Windows или `file:/data/club.db` на сервере. Каталог создаётся автоматически.

Не копируйте `.env.example` поверх уже настроенного `.env`: так можно сбросить секрет сессий и свой путь к БД. Название, часовой пояс, контакты, адрес и срок отмены редактируются в админке.

## Возможности

- Главная, форматы занятий, тренеры, площадки, контакты, адаптивное расписание с фильтрами и выбором дня.
- Регистрация по имени/email/паролю, вход/выход через Passport Local, безопасные HTTP-only сессии express-session, сохранённые в SQLite.
- Групповые, индивидуальные и детские тренировки. Для ребёнка родитель указывает имя и возраст. Индивидуальная тренировка вмещает одного клиента.
- Кабинет: будущие занятия, история, отмена, атомарный перенос, имя/телефон, смена пароля с завершением остальных сессий.
- По умолчанию самостоятельная отмена и перенос доступны за 12 часов до начала; позднее предлагается связаться с администратором.
- Админка: показатели из БД, занятия и серии по дням недели, конфликты до сохранения всей серии, участники/контакты, ручная запись клиента и гостя по телефону, переносы/отмены, посещение/пропуск, поиск клиентов, тренеры/площадки/корты, настройки, журнал действий.
- Гостевая запись не привязывается к аккаунту по совпадению телефона. Архивирование и отмена не удаляют историю.
- Сервер проверяет права, принадлежность записей, вместимость, дубли и пересечения. Публичная регистрация создаёт только клиента. Контакты клиентов не доступны в публичном API.
- Цены хранятся целыми копейками, время — в UTC, отображение и серии используют пояс клуба (`Asia/Vladivostok` по умолчанию). Несуществующее местное время при переводе часов отклоняется.

## SQLite: транзакции и сохранность

WAL включается миграцией. В начале каждой транзакции записи сервер получает блокировку писателя **до чтения свободных мест**. Поэтому два процесса, работающие с одним файлом, не могут одновременно забрать последнее место. Временные конфликты блокировки повторяют транзакцию целиком. Проверки дополнены частичным уникальным индексом и SQLite-триггерами вместимости, пересечений тренера/корта/клиента. Неудачный перенос откатывается целиком: исходная запись остаётся действующей.

Для размещения используйте **один экземпляр API и локальный постоянный диск**. SQLite рассчитана на небольшое приложение; несколько реплик на разных дисках будут иметь разные базы. Общий файл через сетевую файловую систему не используйте.

База, WAL/SHM, `.env` и его резервные копии исключены из Git и Docker-образа. Для резервной копии остановите API и скопируйте каталог `data/` либо используйте согласованный online-backup SQLite. Не копируйте только `.db` во время работы: последние изменения могут находиться в `-wal`.

## Команды и проверки

```powershell
npm run setup          # локальная подготовка и подтверждённые данные клуба
npm run db:generate    # Prisma-клиент
npm run db:migrate     # SQL-миграции без удаления данных
npm run db:seed        # подтверждённые цены, расписание, площадки и тренеры
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Миграции повторяемы, каждая применяется в write-транзакции и записывается с SHA-256 в `_ClubMigration`. Изменённая старая миграция отклоняется. Новые изменения схемы оформляйте новой SQL-миграцией. Не смешивайте этот журнал с `prisma migrate deploy` и не используйте `db push` на рабочей БД. Нативные движки Prisma для API не нужны: используется официальный `@prisma/adapter-libsql` с локальным файлом, **без сервиса Turso и без сетевой базы**.

`npm test` создаёт отдельный временный SQLite-файл, применяет миграции, проверяет конкурентную запись (также из независимых Node-процессов), дубли, отмену, перенос, сроки, пересечения, права, сессии, CSRF, лимиты входа и серии. После тестов временный каталог удаляется; рабочая база не очищается.

Playwright проверяет клиентский и админский сценарии на компьютере и телефоне. Он создаёт тестовые аккаунты в базе из `DATABASE_URL`, поэтому запускайте его на **демобазе**, а не на рабочей. Перед ним нужны `npm run build`, `npm run setup` и `npm run db:seed:demo` на отдельной демобазе. Скриншоты/трассы — в `test-results/`. Если браузер уже установлен, можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

`db:seed` добавляет подтверждённые данные клуба и известных тренеров, не создаёт пользователей и вымышленные занятия. `db:seed:demo` создаёт только демонстрационные занятия для разработки; не запускайте его на рабочей базе.

## REG.RU: фронтенд

Ваша схема размещения сохраняется: REG.RU отдаёт сайт, Node.js на Amvera обрабатывает запросы и хранит SQLite. Файл БД нельзя загружать в публичную папку сайта.

1. Подключите домен и HTTPS для сайта, например `club.ru`.
2. Соберите фронтенд с адресом API:

```powershell
$env:VITE_API_URL="https://api.club.ru"
npm run build:web
```

На Linux/macOS: `VITE_API_URL=https://api.club.ru npm run build:web`.

3. Загрузите **содержимое `dist/web/`** в корень сайта на REG.RU. Не загружайте `.env`, `data/`, исходники или `dist/backend/`.
4. Hash-навигация (`/#/schedule`) работает без правил переписывания URL. При изменении адреса API пересоберите фронтенд.

## Amvera: Node.js и SQLite

Отдельную PostgreSQL создавать не нужно.

- Создайте приложение из `deploy/amvera/Dockerfile` с контекстом сборки в корне репозитория (он нужен только как вариант сборки на хостинге, не для вашего ПК) или используйте Node.js 22.12+ с `npm ci --ignore-scripts && npm run build`.
- Подключите **постоянный диск** к `/data` и задайте `DATABASE_URL=file:/data/club.db`. Каталог должен быть доступен пользователю процесса на запись. Файл вне постоянного диска может потеряться после пересоздания контейнера.
- Выберите **один экземпляр API**. Не настраивайте горизонтальное масштабирование с отдельными копиями файла.
- В защищённых настройках задайте случайный `SESSION_SECRET`, `WEB_ORIGIN=https://club.ru`, `NODE_ENV=production`, `PORT=3001`. При одном доверенном reverse proxy Amvera установите `TRUST_PROXY=1`.
- Команда запуска: `node dist/backend/scripts/migrate.js && node dist/backend/src/index.js`. Dockerfile уже использует её. Порт приложения — 3001; готовность — `/api/health`, с проверкой БД.
- Подключите `api.club.ru` и HTTPS. Сессии в production используют Secure + HTTP-only cookies. Для `club.ru` + `api.club.ru` оставьте `COOKIE_SAME_SITE=lax`. API на чужом домене потребует `none` и HTTPS, но браузеры могут блокировать сторонние cookies, поэтому свой API-поддомен предпочтительнее.
- Создайте администратора в консоли приложения: `node dist/backend/scripts/create-admin.js`. Для демоданных при необходимости: `node dist/backend/prisma/seed.js`.
- Настройте резервное копирование постоянного диска и проверьте вход, запись и сохранение после перезапуска перед открытием сайта.

Вариант с одним Node-приложением тоже доступен: `SERVE_WEB=1`, пустой `VITE_API_URL` при сборке, один домен сайта и API. Автоматическая публикация на хостинг не настроена.

## Структура и границы версии

`frontend/src/` — интерфейс, `backend/src/` — API и правила записи, `backend/prisma/schema.prisma` — модели, `backend/prisma/migrations/` — SQLite SQL с ограничениями, `backend/scripts/` — настройка/миграции/администратор. Прежняя PostgreSQL-миграция сохранена только как справочный архив в `backend/prisma/legacy-postgresql/` и новым мигратором не выполняется.

Материалы демонстрационные: авторская иллюстрация корта, портреты-инициалы, демотренеры/площадки. Контакты клуба нужно заполнить. Нет онлайн-оплаты, SMS, рассылок, абонементов, аренды корта без тренера, восстановления пароля и подтверждения email. Оплата — в клубе.

Листы API ограничены: публичное расписание — 300 будущих занятий, админские записи/занятия — 500, поиск клиентов — 200 результатов, журнал — 100 последних действий. История в БД сохраняется полностью. Серии — до 181 дня. Для публичного запуска также нужны согласованные владельцем тексты о работе с персональными данными.
